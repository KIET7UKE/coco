## Cloud hosting for microservices on Coco: the workload in practical terms

Microservices are a networking problem that looks like a code problem. Each service needs a private name, a limit on CPU and memory, and a deploy that does not require the others to move. A platform that gives every service a public URL and a shared dyno size makes the mess more expensive. Start with two or three processes, not twenty. Coco puts them on one private network, terminates TLS at the edge, and lets you scale the one service that is actually busy. If you cannot name the team that owns a service, it should not be a service yet.
